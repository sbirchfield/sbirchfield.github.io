Lesson 2: Image Arithmetic¶

Since an image is just an array of numbers (Lesson 1), the most basic image edits are just arithmetic: add a constant to brighten, subtract to darken, blend two images by weighted averaging. This lesson looks at that arithmetic in detail — and at a subtlety that trips up almost everyone the first time: images are usually stored as 8-bit unsigned integers, and how you add two of them matters a great deal.

In [1]:
import numpy as np
import cv2
import matplotlib.pyplot as plt

Brightening: just add a constant¶

A pixel's value represents brightness, so adding a positive constant to every pixel should brighten the whole image. Let's try it directly with NumPy.

In [2]:
img = np.zeros((150, 150), dtype=np.uint8)
cv2.circle(img, (75, 75), 50, 180, -1)
cv2.rectangle(img, (20, 20), (60, 60), 220, -1)

brightened_naive = img + np.uint8(80)

fig, axes = plt.subplots(1, 2, figsize=(6, 3.5))
axes[0].imshow(img, cmap='gray', vmin=0, vmax=255)
axes[0].set_title('Original')
axes[1].imshow(brightened_naive, cmap='gray', vmin=0, vmax=255)
axes[1].set_title('img + 80  (naive)')
for ax in axes:
    ax.axis('off')
plt.tight_layout()
plt.show()

Look closely at the bright rectangle (originally 220): it should have become blindingly bright, but instead it looks darker than the circle around it. Something has gone wrong.

The problem: uint8 overflow¶

An 8-bit unsigned integer can only represent 0-255. 220 + 80 = 300, which doesn't fit — NumPy's uint8 arithmetic wraps around (like a car odometer rolling over), silently computing 300 mod 256 = 44 instead of clamping at 255. This is exactly the same fixed-width overflow behavior any low-level integer type has; NumPy just applies it silently, with no warning.

In [3]:
sample_values = np.array([200, 250, 220], dtype=np.uint8)
wrapped = sample_values + np.uint8(80)

print('original values:      ', sample_values)
print('naive (uint8) + 80:   ', wrapped, '  <- wrapped around, not clamped!')
print('what we actually want:', np.clip(sample_values.astype(int) + 80, 0, 255))

original values:       [200 250 220]
naive (uint8) + 80:    [24 74 44]   <- wrapped around, not clamped!
what we actually want: [255 255 255]

The fix: saturating arithmetic¶

OpenCV's arithmetic functions (cv2.add, cv2.subtract, ...) use saturating arithmetic instead: results are clamped to the valid range (0-255 for uint8) rather than wrapping. This is almost always what you actually want for image brightness.

In [4]:
brightened_saturated = cv2.add(img, np.full_like(img, 80))

print('rectangle pixel value, original:  ', img[40, 40])
print('sample pixel, naive (wrapped):    ', brightened_naive[40, 40])
print('sample pixel, cv2.add (saturated):', brightened_saturated[40, 40])

fig, axes = plt.subplots(1, 3, figsize=(9, 3.5))
for ax, im, title in zip(axes, [img, brightened_naive, brightened_saturated],
                          ['Original', 'img + 80 (wraps)', 'cv2.add (saturates)']):
    ax.imshow(im, cmap='gray', vmin=0, vmax=255)
    ax.set_title(title, fontsize=9)
    ax.axis('off')
plt.tight_layout()
plt.show()

rectangle pixel value, original:   220
sample pixel, naive (wrapped):     44
sample pixel, cv2.add (saturated): 255

With saturation, every pixel gets brighter or stays at the maximum — never wraps around to become darker. The same idea applies to cv2.subtract at the bottom end (clamped at 0 instead of wrapping to a large positive number).

Brightening only part of an image, with a mask¶

Often you want to adjust brightness selectively — e.g. lighten a foreground subject without touching the background. Given a binary mask (Lesson 3 will build these algorithmically; here we just draw one), only copy the brightened result where the mask is set.

In [5]:
photo = np.full((150, 150), 100, dtype=np.uint8)
cv2.rectangle(photo, (40, 40), (110, 110), 130, -1)

foreground_mask = np.zeros((150, 150), dtype=np.uint8)
cv2.circle(foreground_mask, (75, 75), 40, 255, -1)

fully_brightened = cv2.add(photo, np.full_like(photo, 60))
result = photo.copy()
result[foreground_mask > 0] = fully_brightened[foreground_mask > 0]

fig, axes = plt.subplots(1, 3, figsize=(9, 3.5))
for ax, im, title in zip(axes, [photo, foreground_mask, result],
                          ['Original', 'Mask (foreground)', 'Only foreground brightened']):
    ax.imshow(im, cmap='gray', vmin=0, vmax=255)
    ax.set_title(title, fontsize=9)
    ax.axis('off')
plt.tight_layout()
plt.show()

print(f'brightness inside mask:  {result[75, 75]}')
print(f'brightness outside mask: {result[5, 5]}')

brightness inside mask:  190
brightness outside mask: 100

cv2.add (and several other OpenCV functions) also accept a mask argument directly, which does exactly this select-and-copy in one call: cv2.add(photo, 60, mask=foreground_mask) — only writes into the masked region, leaving the rest of the destination untouched.

Blending two images¶

A weighted sum of two images — a cross-dissolve — is the same saturating arithmetic, generalized: cv2.addWeighted(a, alpha, b, beta, gamma) computes a*alpha + b*beta + gamma, saturated.

In [6]:
img_a = np.zeros((120, 120), dtype=np.uint8)
cv2.rectangle(img_a, (10, 10), (90, 90), 220, -1)

img_b = np.zeros((120, 120), dtype=np.uint8)
cv2.circle(img_b, (80, 80), 40, 220, -1)

fig, axes = plt.subplots(1, 5, figsize=(13, 3))
for ax, alpha in zip(axes, [0.0, 0.25, 0.5, 0.75, 1.0]):
    blended = cv2.addWeighted(img_a, 1 - alpha, img_b, alpha, 0)
    ax.imshow(blended, cmap='gray', vmin=0, vmax=255)
    ax.set_title(f'alpha={alpha}', fontsize=9)
    ax.axis('off')
plt.tight_layout()
plt.show()

Difference imaging¶

Subtracting two images (with an absolute value, so both directions of change matter equally) highlights exactly what's different between them — the basis of simple motion/change detection, and something we'll reuse when comparing reconstructions against ground truth in later lessons.

In [7]:
before = np.zeros((120, 120), dtype=np.uint8)
cv2.circle(before, (50, 60), 30, 200, -1)

after = np.zeros((120, 120), dtype=np.uint8)
cv2.circle(after, (70, 60), 30, 200, -1)  # the circle moved

difference = cv2.absdiff(before, after)

fig, axes = plt.subplots(1, 3, figsize=(9, 3.5))
for ax, im, title in zip(axes, [before, after, difference], ['Before', 'After', 'cv2.absdiff']):
    ax.imshow(im, cmap='gray', vmin=0, vmax=255)
    ax.set_title(title, fontsize=9)
    ax.axis('off')
plt.tight_layout()
plt.show()

The difference image is zero everywhere nothing changed, and bright exactly where the circle used to be or now is — the overlapping middle region, present in both frames, correctly comes out as zero difference.

Exercise¶

  1. Predict, then check, what cv2.subtract(img, 150) does to a pixel whose value is 100 — does it wrap around like the naive NumPy addition did, or saturate?
  2. Use cv2.add with its mask argument directly (instead of manually copying with boolean indexing as done above) to reproduce the masked-brightening result, and confirm the two approaches give identical output.
  3. cv2.addWeighted requires alpha + beta to not necessarily sum to 1 (the gamma term is added on top of both). Try cv2.addWeighted(img_a, 1.0, img_b, 1.0, 0) (a plain saturating sum, not a blend) and describe what changes about the result compared to alpha=0.5.
