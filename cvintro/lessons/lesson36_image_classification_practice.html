Lesson 36: Image Classification in Practice¶

Every classifier so far has been evaluated with a single number: overall accuracy. That number hides a lot. This lesson builds a 4-class classifier on a deliberately imbalanced subset of CIFAR-10 — real photographs, not synthetic shapes — and shows why accuracy alone can be misleading, using the tools that reveal what's actually going wrong: the confusion matrix, and per-class precision and recall.

A 4-class, imbalanced dataset¶

Four real photo categories from CIFAR-10 (Krizhevsky, 2009): cat, dog, automobile, and truck. The test set has an even 150 images per class, but the training set is deliberately starved of trucks (90 examples, versus 400 each for the other three) — a stand-in for the common real-world situation where some classes are just rarer to collect than others. Cat and dog are included deliberately as a visually similar pair, regardless of how much training data either gets.

def load_cifar_batch(path):
    with open(path, 'rb') as f:
        d = pickle.load(f, encoding='bytes')
    imgs = d[b'data'].reshape(-1, 3, 32, 32).transpose(0, 2, 3, 1).astype(np.float32) / 255.0
    labels = np.array(d[b'labels'], dtype=np.int64)
    return imgs, labels

    train_imgs.append(imgs); train_labels.append(labels)

test_imgs, test_labels = load_cifar_batch(CACHE_DIR / 'test_batch')

rng = np.random.default_rng(7)

def subset_for_classes(imgs, labels, per_class_counts):
    out_imgs, out_labels = [], []
    for i, name in enumerate(CLASSES):
        idx = np.where(labels == CLASS_IDS[name])[0]
        idx = rng.permutation(idx)[:per_class_counts[name]]
        out_imgs.append(imgs[idx])
        out_labels.append(np.full(len(idx), i, dtype=np.int64))
    out_imgs, out_labels = np.concatenate(out_imgs), np.concatenate(out_labels)
    perm = rng.permutation(len(out_imgs))
    return out_imgs[perm], out_labels[perm]

# training set: cat/dog/automobile well represented, truck deliberately starved

X_test, y_test = subset_for_classes(test_imgs, test_labels,

class CNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv = nn.Sequential(
            nn.Conv2d(3, 16, 5, padding=2), nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 5, padding=2), nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(),
            nn.AdaptiveMaxPool2d(1),
        )
        self.fc = nn.Linear(64, 4)

    def forward(self, x):
        return self.fc(self.conv(x).flatten(1))

torch.manual_seed(0)
model = CNN()
opt = torch.optim.Adam(model.parameters(), lr=0.0007)
Xt = torch.tensor(X_train).permute(0, 3, 1, 2); yt = torch.tensor(y_train)
for _ in range(150):
    opt.zero_grad()
    loss = F.cross_entropy(model(Xt), yt)
    loss.backward()
    opt.step()

Xte = torch.tensor(X_test).permute(0, 3, 1, 2)
with torch.no_grad():
    preds = model(Xte).argmax(1).numpy()

acc = (preds == y_test).mean()
print(f'overall test accuracy: {acc:.1%}')

overall test accuracy: 50.3%

Just over 50% overall accuracy, on a 4-class task where chance is 25%, sounds like a reasonable result for a small from-scratch CNN on real photos. It hides something important: the model is not equally good at all four classes.

Confusion matrix¶

Row i, column j counts test examples of true class i predicted as class j. A perfect classifier is diagonal; everything off the diagonal is a specific, nameable mistake.

True positives, false positives, true negatives, false negatives¶

Every cell of the confusion matrix above is a specific kind of correctness or mistake, but the standard vocabulary for talking about them is binary: pick one class and ask only "is it this, or not?" Collapsing the 4-class matrix down to "truck vs. everything else" gives exactly four outcomes:

  • True positive (TP): actually a truck, predicted truck. A hit.
  • False negative (FN): actually a truck, predicted something else. A miss — the model let it slip past.
  • False positive (FP): actually not a truck, predicted truck anyway. A false alarm.
  • True negative (TN): actually not a truck, correctly predicted not-truck.

This is the same 2x2 table underlying every binary classifier's evaluation (a medical test's "positive/negative" result, a spam filter's "spam/not spam" decision) — a multi-class confusion matrix is just this table computed once per class, with everything off that class's row/column collapsed into "not this class."

Precision and recall¶

Two numbers per class, computed directly from TP/FP/FN:

  • Recall = TP / (TP + FN) — of everything that really was class i, what fraction did the model catch? Low recall means the model misses that class often.
  • Precision = TP / (TP + FP) — of everything the model called class i, what fraction actually was? Low precision means the model cries wolf on that class often.

(A less commonly needed but related pair, built from the other two quadrants: specificity = TN / (TN + FP), how well the model avoids false alarms on the negative class, and its complement the false positive rate = FP / (FP + TN) = 1 − specificity.)

Bayes' rule¶

To see why precision behaves the way it does, it may help to recognize a deeper connection. Bayes' rule relates a conditional probability to its reverse: $P(A\mid B) = P(B\mid A)\,P(A)\,/\,P(B)$. Bayes' rule connects precision, $P(\text{actually } i\mid\text{predicted } i)$, with sensitivity/specificity, $P(\text{predicted } i\mid\text{actually } i)$:

$$P(\text{actually } i\mid\text{predicted } i) = \frac{P(\text{predicted } i\mid\text{actually } i)\,P(\text{actually } i)}{P(\text{predicted } i)}.$$

The $P(\text{actually } i)$ term — the base rate or prior, how common class i is to begin with — matters just as much as how good the classifier is.

The classic illustration: a disease with 1% true prevalence, and a test that's "99% accurate" (99% sensitivity, 99% specificity). You test positive — what's the chance you actually have it? Intuition says ≈99%, but the real answer is closer to 50%. The reason: Out of 10,000 people, 100 actually have the disease, and the test catches 99 of them (TP=99). Of the 9,900 healthy people, a 1% false-positive rate flags about 99 more (FP=99) — so among everyone who tests positive, only about half actually has the disease: precision = 99/198 ≈ 50%, nowhere near 99%. A low base rate lets false positives from the enormous healthy majority swamp the true positives from the rare, small minority.

Truck shows the same effect: it's the rarest class here, and even its respectable 72% precision (table above) is already fighting the same uphill arithmetic that makes precision (also known as "positive predictive value") punishing for any rare condition, medical or otherwise.

Precision-recall curve¶

So far, each class's precision and recall came from a single, fixed decision rule: whichever class scores highest wins (hard argmax). But the model doesn't actually output a single verdict — for "truck vs. everything else," it outputs a continuous score (the softmax probability assigned to truck) for every test image. Thresholding that score directly and sweeping the threshold from 0 to 1 traces out a precision-recall curve: the complete tradeoff between catching more trucks and crying wolf less often. Hard argmax isn't quite the same decision rule — it depends on how truck's score compares to the other three classes, not just whether it clears some fixed number — so the point it actually lands on (marked in red) sits close to, but not exactly on, this single-score curve.

The raw curve below is jagged: with so few truck examples, a single unlucky (or lucky) false positive can make precision dip and then recover as the threshold relaxes further, which isn't a real change in the underlying tradeoff — just noise from a small test set. The standard fix (used, for instance, to compute "average precision") is to replace each point's precision with the best precision achieved at that recall or higher, producing a monotonically non-increasing envelope that casts a "shadow" leftward over the noisy dips.

In [7]:
with torch.no_grad():
    probs = F.softmax(model(Xte), dim=1).numpy()

scores = probs[:, cls]          # softmax probability assigned to 'truck'
is_truck = (y_test == cls)

thresholds = np.linspace(0, 1, 101)
precisions, recalls = [], []
for t in thresholds:
    pred_pos = scores >= t
    tp_t = (pred_pos & is_truck).sum()
    fp_t = (pred_pos & ~is_truck).sum()
    fn_t = (~pred_pos & is_truck).sum()
    precisions.append(tp_t / (tp_t + fp_t) if tp_t + fp_t > 0 else 1.0)
    recalls.append(tp_t / (tp_t + fn_t) if tp_t + fn_t > 0 else 0.0)

# the raw curve is jagged (precision isn't monotonic as the threshold relaxes --
# one unlucky false positive can make it dip, then recover). The standard fix,
# used e.g. to compute "average precision": replace each point's precision with
# the BEST precision achieved at that recall or higher -- a monotonically
# non-increasing envelope that "casts a shadow" leftward over the noisy dips.
# Different thresholds can land on the exact same recall (relaxing the
# threshold past a non-truck image changes precision but not recall), so ties
# are first collapsed to their best precision before taking the running max --
# otherwise a later, worse-precision point at the same recall can silently
# undercut an earlier, better one.
order = np.argsort(recalls)
r_sorted = np.array(recalls)[order]
p_sorted = np.array(precisions)[order]
uniq_r, inverse = np.unique(r_sorted, return_inverse=True)
uniq_p = np.zeros_like(uniq_r)
np.maximum.at(uniq_p, inverse, p_sorted)
envelope = np.maximum.accumulate(uniq_p[::-1])[::-1]

plt.plot(recalls, precisions, marker='.', color='#aac4e0', linewidth=1.2, label='raw (noisy)')
# where='pre': each point's value extends LEFTWARD (toward lower recall) onto
# the gap before it -- matching max_{r'>=r} P(r'), and leaving points that are
# already their own local max untouched, instead of dragging a peak forward
# onto later points that don't need it.
plt.step(uniq_r, envelope, where='pre', color='#1f6fb4', linewidth=2.2,
          label='envelope (monotonic)')
plt.scatter([tp / (tp + fn)], [tp / (tp + fp)], color='red', marker='x', s=60, zorder=5,
            label='hard-argmax point')
plt.xlabel('recall'); plt.ylabel('precision')
plt.title('truck: precision-recall curve as the decision threshold sweeps')
plt.legend(fontsize=8)
plt.show()

The animation below makes the mechanism behind that curve concrete: a threshold sweeps across every test image's truck score (sorted left to right), coloring each one TP/FP/FN/TN live as it crosses, while the (recall, precision) point crawls along the same curve shown above.

Truck — the class starved to 90 training images, versus 400 for each other class — has high precision but low recall: when the model does say "truck," it's usually right, but it fails to recognize the overwhelming majority of actual trucks, defaulting instead to whichever classes it saw plenty of during training (mostly "automobile," the visually closest well-represented class). That is the standard signature of class imbalance, and it is completely invisible in the single overall-accuracy number from before. Cat and dog, by contrast, are both well-represented in training but get confused with each other far more than with automobile or truck — a different failure mode entirely, caused by genuine visual similarity between the two animals rather than by lack of data. Automobile ends up with unusually high recall but not-so-great precision, for the same reason truck's recall suffered: it's absorbing the starved truck class's misclassifications, since "wheeled vehicle" is an easy fallback guess once the model can't tell trucks apart from automobiles.

The practical lesson: always inspect the confusion matrix and per-class metrics before trusting a single accuracy figure, especially on a dataset where classes aren't balanced.
